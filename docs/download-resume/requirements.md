# 目标
  将 UUGet 的下载续传能力从"仅同会话内、仅 HTTP Range 直链"的有限实现，升级为覆盖全部下载路径、可跨会话恢复、失败不丢进度、且对用户可
  解释的可靠下载体系；在保证数据完整性的前提下，使用户在任何中断场景下都能从最近一次有效进度继续，而不是从零开始。

  # 现状基线（事实锚点）
  - 仅 HTTP 直链 Range 分块路径支持会话内暂停/恢复：确定性 OPFS 文件名、内存态 RangeResumeRegistry、Range + If-Range、按块 writeAt。锚
  点：chrome-extension/src/offscreen/lib/http-download.ts、chrome-extension/src/offscreen/download_worker/main.ts、range-resume.ts。
  - 任务账本存 chrome.storage.session，chunk 账本 mediaDownloadsStorage 亦为 Session 级；offscreen 启动 GC 全量清理 OPFS，导致浏览器重
  启/扩展重载后进度必然丢失。
  - 非暂停失败会删除 OPFS 输入；mux 失败同样删除已完成的输入文件。
  - HLS/DASH 使用 Date.now() 命名且异常全删，仅支持重下；流式回退（无 Range）无法按偏移请求。
  - 下载 key 为 crypto.randomUUID()，重新检测同一资源无法命中已有进度。
  - 续传要求强 ETag；弱 ETag / 仅有 Last-Modified 的源一律不可续传。
  - 已有 unlimitedStorage 权限；未显式调用 navigator.storage.persist()。

  # 范围
  ## 包含
  1. 失败保进度与失败分类处理。
  2. 稳定资源身份与跨会话续传（浏览器重启、扩展重载、崩溃恢复）。
  3. 传输中断后的自动暂停与自动恢复。
  4. HLS / DASH 分片级续传。
  5. 续传校验能力增强（无强 ETag 源、chunk 内断点、签名 URL 过期）。
  6. 续传体验与存储治理（能力告知、状态透明、保留策略、批量操作、诊断）。

  ## 不包含
  - 不改变 chrome.downloads 原生下载自身的续传行为。
  - 不实现跨设备或云端同步。
  - 不为直播流提供"续传"；直播必须明确标注不可续传并按明确语义处理。
  - 不引入服务端组件。

  # 不可违背的原则
  1. 完整性优先：任何恢复必须先验证资源一致性（强 ETag、Last-Modified、总长度、manifest 哈希、分片索引、边界抽样校验之一或组合）；验证
  失败必须显式降级为全量重下并向用户说明原因，禁止静默拼接可能损坏的文件。
  2. 暂停保留、取消清理：pause 保留 OPFS 与进度账本；cancel 必须清理全部相关文件与账本，语义不得改变。
  3. 进度单调：恢复后用户可见进度不得回退；允许短暂显示"校验中"，但不得从 38% 闪回 0% 后静默继续。
  4. 用户可解释：任何"无法续传/已重新开始"都必须给出可读原因，禁止无提示归零。
  5. 架构兼容：保持 MV3 + offscreen + download worker 的既有职责边界，不引入常驻后台进程，不破坏现有测试与现有会话内续传语义。
  6. 不得以降低校验强度换取续传成功率。

  # 分阶段目标与验收标准
  ## M0 失败保进度
  实现：
  - 将失败分类为传输失败、mux/转码失败、数据完整性失败。
  - 传输失败：保留 OPFS 与 chunk 账本，任务进入可重试的失败态；Retry 仅补下载缺失块。
  - mux/转码失败：保留已完成的输入文件，Retry 仅重跑 mux。
  - 数据完整性失败：清理并按原则 1 显式告知。
  - HLS/DASH 在下载已完成、mux 失败时不得删除输入分片文件。
  验收：
  - 模拟 50% 处单块持续 403：Retry 后已下载字节数不减少，仅缺失块产生网络请求。
  - 注入 mux 失败：Retry 不触发任何媒体字节重下。
  - 最终产物通过长度与身份校验；新增对应单元/集成测试。

  ## M1 稳定资源身份与跨会话账本
  实现：
  - 任务账本与 chunk/分片账本迁移至 storage.local，带 schemaVersion、TTL 与迁移逻辑。
  - OPFS GC 改为保留可续传文件：默认 TTL 7 天且可配置，支持按容量 LRU 清理；cancel 立即清理。
  - 引入内容指纹（URL + ETag/Last-Modified + 总大小；HLS 增加 manifest 哈希）作为可复用下载身份，替代仅靠随机 requestId 命中进度。
  - 启动时恢复 paused / 中断任务，UI 展示并提供"继续全部"。
  验收：
  - 下载至 50% 暂停 → 关闭并重启浏览器 → 任务仍可见，恢复从最近完成块继续，网络请求只覆盖缺失区间。
  - 重新检测同一媒体并发起下载：命中已有进度并提示"从 X% 继续"。
  - 超过 TTL 的 partial 文件被清理；取消任务不残留文件与账本；无孤儿文件持续增长。

  ## M2 自动恢复
  实现：
  - 瞬时传输失败（超时、断网、休眠唤醒、连接重置）自动进入 paused 并按退避策略重试，网络恢复后自动继续，无需用户操作。
  - 重试耗尽后进入"可恢复失败"而非清零。
  验收：
  - 下载中断网 30 秒：恢复后自动继续，进度不归零。
  - 休眠唤醒后自动继续。
  - 不产生无限重试；用户 cancel 仍可立即终止。

  ## M3 HLS / DASH 分片级续传
  实现：
  - 以 manifest 哈希 + 轨道标识 + 分片索引建立分片账本；音视频轨独立续传。
  - VOD 支持暂停/跨会话续传；playlist 变化、序列号漂移或直播场景显式降级为全量重下并提示原因。
  - 分片内部采用可校验的原子写入，避免半片数据被当作完成。
  验收：
  - HLS VOD 暂停于 50% → 恢复仅请求未完成分片。
  - 视频轨已完成、音频轨未完成时，恢复仅续传音频。
  - playlist 变化时给出明确提示且输出文件通过时长/大小校验。
  - 直播流不出现"续传"入口或错误承诺。

  ## M4 校验与覆盖增强
  实现：
  - 支持仅有 Last-Modified 的源通过 If-Range 日期形式续传；无任何验证器时使用"总长度 + 边界抽样比对"建立可信续传，并在 UI 标明校验方
  式。
  - chunk 内断点：按不超过 1MB 的粒度持久化已落盘偏移。
  - 续传遇 403/410（签名 URL 过期）：自动重新解析源 URL/请求头一次，失败则保留进度并提示重新检测源。
  - 最终产物交付阶段支持跨会话恢复：产物短期保留并可重新投递。
  验收：
  - 弱验证器源可成功续传且通过抽样校验；不匹配时自动全量重下并提示。
  - 最坏情况下单连接重下量不超过 1MB。
  - 过期 URL 场景不丢进度，提示可操作。
  - 产物已生成但浏览器下载中断后，重启仍可重新投递。

  ## M5 体验与治理
  实现：
  - 开始前探测并展示续传能力；不可续传场景的按钮语义为"停止"或明确标注"将重新下载"，不得误导为可续传的"暂停"。
  - 暂停态展示已缓存字节、续传起点与预计剩余下载量；恢复后提示"已从 X% 续传"。
  - 显式调用 navigator.storage.persist()；设置页提供"部分下载缓存"管理入口与 TTL 配置。
  - Wi-Fi 切蜂窝时自动暂停并提示，避免后台消耗计量流量。
  - 提供全部暂停/全部恢复；详情页展示续传失效原因（验证器变化、文件被清理、Range 不匹配等）。
  验收：
  - 各下载模式的按钮语义与实际行为一致，无虚假承诺。
  - 用户可在设置页查看并清理部分下载缓存。
  - 续传失效时详情页显示具体原因。
  - 批量暂停/恢复可用且不破坏单任务状态机。

  # 全局验收标准（Definition of Done）
  1. 所有下载路径（HTTP 直链、合并音视频各轨道、HLS、DASH、流式回退、mux 阶段、交付阶段）均具备明确的续传语义，并有对应测试。
  2. 任何恢复均通过一致性校验；存在"验证器不匹配/长度不符/manifest 变化"的负向测试，确保不会产出损坏文件。
  3. 浏览器重启、扩展重载、网络中断、mux 失败、单块失败五类场景均有可复现的验收用例与通过记录。
  4. 现有测试全部通过；新增单元、集成、端到端测试覆盖上述场景。
  5. 用户可见行为与文档一致：README / CHANGELOG 更新能力矩阵，明确标注各模式的续传能力与限制。
  6. 取消与 TTL 清理后无孤儿文件；OPFS 占用不会无限增长。

  # 测试与证据要求
  - 单元测试：账本 schema 与迁移、TTL/LRU 清理、身份指纹匹配、失败分类、分片索引校验、抽样校验。
  - 集成测试：本地 HTTP 夹具服务器，覆盖 Range/强 ETag、仅 Last-Modified、无 Range、签名过期、playlist 变化、单块持续失败。
  - 端到端测试：浏览器重启恢复、扩展重载恢复、断网自动恢复、mux 失败重试、跨会话产物重新投递。
  - 每个里程碑交付时必须报告：改动文件清单、执行的测试命令与结果、手工验收步骤与证据；未达标项必须明确列出，不得降低验收标准。

  # 执行约束
  - 按 M0 → M5 顺序推进，每个里程碑独立可验收；前一里程碑未通过验收不得进入下一阶段。
  - 不得跳过完整性校验，不得以"提升成功率"为由放宽验证。
  - 若某场景在现有协议或架构下客观不可实现（如无 Range 源的字节级续传），必须给出明确结论、降级方案与用户提示，而不是静默忽略。
