# 目标与边界

## 目标

将 Vidsy 的媒体处理能力从固定的 H.264/AAC 假设升级为由真实媒体特征驱动的通用 remux 系统。对于已合法捕获且未受 DRM 保护的常见网页媒体，系统应选择兼容输出容器并优先执行无损 stream copy；支持范围内的输入必须生成非空、结构有效、可播放的文件。

目标完成后，以下代表性输入不得依赖站点知识：

- MPEG-TS HLS 中的 H.264 + AAC；
- MPEG-TS HLS 中的 HEVC/H.265 + AAC；
- fMP4 HLS 中的常见 MP4 codec；
- DASH 中分离的视频与音频轨；
- MP4、WebM/Matroska 等直接 HTTP 媒体；
- 用户明确请求的音频转 MP3。

## 产品结果

1. 下载策略由输入 codec、轨道、分段格式和目标容器共同决定，不再仅由 `MediaKind` 或 URL 后缀决定。
2. 系统优先保留原始音视频码流；视频转码不属于本目标。
3. 输出文件扩展名、MIME 和真实容器一致。
4. 媒体处理器失败、空输出、缺失必要轨道或结构无效必须表现为失败，不得进入成功历史。
5. 对当前能力不支持的组合，用户获得稳定、可诊断的原因，而不是损坏文件。
6. 能力对站点无感；新增兼容站点不要求增加 provider extractor。

## 非目标

- 解析站点私有页面状态以寻找另一条兼容媒体 URL；
- 根据主机名、页面路径或 CDN URL 模式选择处理策略；
- 绕过 DRM、付费、鉴权或访问控制；
- 隐式降低清晰度或切换到站点隐藏的备用 representation；
- 视频重编码、画质增强、帧率转换或字幕烧录；
- 承诺处理任意 FFmpeg 支持的格式；
- 为失败输入保留扩展名与内容不一致的“尽力而为”文件。

## 核心原则

### 媒体事实优先

codec、轨道和容器必须来自 manifest 元数据、初始化段或媒体探针。URL、文件名和站点名称只可作为展示提示，不可成为能力判断的权威。

### 单一规划权威

一个纯函数式 planner 负责把探测结果与用户意图转换为执行计划。HLS、DASH、direct HTTP 和 merged 下载适配器提供事实和执行原语，不得各自维护互相漂移的 codec/container 决策表。

### 无损优先

默认计划使用 `-c copy` 或等价的无损拼装。只有用户明确请求 MP3 时允许音频转码。无法无损产出兼容容器时，应返回 `unsupported`，而不是偷偷转码视频。

### 成功可证明

“成功”必须同时满足：

- 媒体处理器退出码为零；
- 最终文件大小大于零；
- 文件探针可识别真实容器；
- 必要轨道存在；
- 输出 codec 与执行计划一致；
- 浏览器下载进入完成状态。

## 完成定义

只有以下条件全部满足，目标才算完成：

1. [`02-architecture-contract.md`](./02-architecture-contract.md) 中的 planner、capability、执行和产物契约已落地；
2. 通用 WASM 变体可 remux HEVC + AAC MPEG-TS HLS 为有效 MP4；
3. [`04-validation.md`](./04-validation.md) 的必选矩阵全部通过；
4. 现有 H.264 HLS、DASH、direct HTTP、merged A/V 和 MP3 路径无回归；
5. Chrome 扩展生产构建通过，WASM 产物可复现并具有完整许可证与来源说明；
6. 没有新增站点专用 extractor、host 分支或 URL codec 猜测；
7. 任何失败路径均不会留下被记录为成功的 0-byte 或结构损坏文件。

## 决策升级条件

首选单个精简的 `web-media-remux` WASM 变体。只有在实测证明其压缩后扩展体积、初始化延迟或运行内存不可接受时，才允许设计基础/扩展两个按需加载的变体。该决策必须有同机多轮测量、包体差异和加载路径复杂度证据，不得仅凭预期优化拆分。
